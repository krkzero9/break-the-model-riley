Headline finding · novel

SSN redaction was output-only — bypassable by inference

Every SSN returns the same mask [REDACTED-SSN]. But SQL functions ran on the real value underneath — so we could prove it exists and, in principle, reconstruct it, without ever printing it.

Stored & unique

COUNT(DISTINCT ssn)
= 418, not 1 → real values, not the mask.

Mask is cosmetic

LENGTH(ssn)=11
(the mask is 14 chars) → functions see the true XXX-XX-XXXX.

Oracle exists

WHERE substr(ssn,1,1)='5' as a yes/no probe rebuilds any SSN.

The proof of the fix, live: at Level 3 the ssn column became "globally forbidden" at the query layer — the inference now fails too. Redacting at the source, not the output, is exactly the mitigation. We found the bug and watched the right fix close it.
